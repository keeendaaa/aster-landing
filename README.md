# aster-landing

Лендинг модуля абсолютной коррекции навигации для гражданских платформ. Звёздный сценарий — основа концепции; ориентирование по Солнцу исследуется отдельно. GPS/ГЛОНАСС не заменяет.

Все пункты документа с правками и их проверки: [docs/revisions.md](docs/revisions.md).

## Запуск

```sh
npm install
npm run dev
```

Открыть адрес, который выводит Vite (по умолчанию http://localhost:5173).

```sh
npm run build
npm run preview
```

`dist/` — статическая часть сайта. Для отправки заявок также нужна функция `api/contact.js` на Vercel; обычный Vite dev/preview её не запускает.

## Что внутри

- React 19, TypeScript, Vite.
- Настоящие компоненты React Bits: **GooeyNav**, **AnimatedContent**, **Magnet**. Исходники из официального реестра `https://reactbits.dev/r/{Name}-TS-CSS.json` находятся в `src/components/reactbits/`.
- GSAP + ScrollTrigger + useGSAP: последовательное появление первого экрана, появления секций, параллакс видео, движение большого логотипа в футере.
- Product Sans для всех крупных заголовков и Manrope для остального текста, с кириллицей и локальной загрузкой без CDN.
- Ваше восьмисекундное видео в хиро, с постером, паузой, отключением автоматического воспроизведения при reduced motion и остановкой за пределами экрана.
- Отдельная копия вашего автономного демо, перекрашенная в синие/ледяные тона. Кнопки на лендинге управляют его реальной временной шкалой. Родные play/pause, ползунок и клавиатура сохранены.
- Аккордеон FAQ, мобильное меню и отправка заявок в Telegram через серверную функцию Vercel.

## Файлы

### shadcn / Tailwind / FAQ

TypeScript уже настроен. Добавлены Tailwind CSS 4 с официальным Vite-плагином и shadcn-совместимая структура:

- `src/components/ui/` — общие UI-компоненты (`@/components/ui` через алиас `@ → src`). Это эквивалент `/components/ui` для проекта с исходниками в `src`; отдельная папка в корне создала бы второй, несовместимый с алиасами путь.
- `src/components/ui/faqs-component.tsx` — двухколоночный FAQ с пятью вопросами Aster и встроенными ссылками на разделы страницы. Основа — код, предоставленный пользователем; это не результат установки платного реестра.
- `src/components/ui/demo.tsx` — демонстрационный импорт того же FAQ без дублирования данных.
- `src/components/ui/accordion.tsx`, `button.tsx` — предоставленные shadcn/Radix-примитивы.
- `src/lib/utils.ts` — `cn` на основе `clsx` и `tailwind-merge`.
- `src/tailwind.css` — Tailwind-утилиты, анимации аккордеона и привязка shadcn-цветов к токенам Aster. Preflight намеренно не подключён: исходные стили сайта не сбрасываются.
- `components.json` — пути и авторизованные реестры React Bits Starter/Pro. Для платной CLI-установки нужен `REACTBITS_LICENSE_KEY` в локальном окружении или `.env.local`; ключ не должен иметь префикс `VITE_` и не должен попадать в Git.

Проект остаётся на Vite: `next/link` заменён обычными якорными ссылками с реальными целями. Устанавливать Next.js только ради них не нужно. FAQ не требует изображений, новых глобальных провайдеров или внешнего хранилища состояния; одиночное раскрытие и клавиатуру обрабатывает Radix Accordion.

Для установки этих зависимостей в новой копии достаточно `npm install`. Эквивалент первоначальной настройки Tailwind:

```sh
npm install -D tailwindcss @tailwindcss/vite
npm install @radix-ui/react-slot @radix-ui/react-accordion class-variance-authority clsx tailwind-merge tw-animate-css
```

- `src/App.tsx` — содержание и интерактивность.
- `src/styles.css` — оформление и адаптивная композиция.
- `src/experience.css` — единый визуальный язык новых секций, инструментов и Anatomy-сцен.
- `src/components/figures/` — интерактивный модуль, установка на коптер и модель звёздного рисунка.
- `scripts/build-figures.mjs` — построение геометрии Anatomy: корпус, оптика, электроника и коптер.
- `public/figures/module.json`, `drone.json` — предвычисленные SVG-детали; загружаются при приближении соответствующей секции, не входят в стартовый JS-бандл.
- `src/demo-theme.css` — отдельная цветовая тема встроенного демо.
- `public/demo/index.html` — автономная адаптированная копия демо.
- `public/media/` — видео, постер, четыре изображения из вашей демонстрации.
- `scripts/prepare.mjs` — первоначальное копирование исходников и применение темы. Требует исходных локальных файлов; для обычного запуска не нужен. Уже установленные React Bits компоненты не перезаписывает.
- `scripts/capture-assets.mjs` — пересъёмка фрагментов демонстрации; требует запущенный Vite, Chrome и `cwebp`.

В AnimatedContent внесены две адаптации: статический контент виден до установки анимации, а при reduced motion перемещение отключается. Изменения локализованы в самом компоненте.

## Перед публикацией

Форма отправляет заявку через `POST /api/contact` в Telegram после согласия пользователя. На Vercel задаются серверные переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` без префикса `VITE_`. Значения не должны попадать в Git или браузер. Бот используется как получатель заявок, а не диалоговый ассистент; webhook и постоянно работающий процесс не требуются. Успех показывается только после подтверждения Telegram. Есть валидация, проверка источника и honeypot; полноценный антиспам/rate limiting пока не подключён.

Характеристики прибора, клиенты, результаты испытаний и контакты не выдуманы. Изображения являются фрагментами концептуального макета, а не фотографиями Aster или испытаниями. Посадка на провод не представлена как функция звёздного датчика.

Все иллюстрации и видео предоставлены пользователем; внешних стоковых изображений нет. Права на публикацию исходных материалов нужно подтвердить перед публичным размещением. Manrope распространяется с лицензией в пакете `@fontsource-variable/manrope`. Product Sans взят из локального файла пользователя `/Users/kenda/Library/Fonts/productsans.ttf`; наличие файла не подтверждает права на веб-использование. Перед публикацией нужно проверить соответствующую лицензию.

## Проверки

При запущенном Vite:

```sh
npm test
```

Тест открывает настоящий Chrome на 1440, 768 и 390 px, проверяет отсутствие горизонтального переполнения, длину основных заголовков, навигацию, управление реальным демо, FAQ и форму с подменённым ответом доставки (не отправляет тестовые заявки в Telegram). Дополнительно проверяет reduced motion, ошибки JS и отсутствующие ресурсы. Серверная валидация и ошибки доставки: `node scripts/check-contact.mjs`. Путь к Chrome можно переопределить через `CHROME_PATH`, URL — через `TEST_URL`.

После переработки тест также проверяет разборку и сборку модуля, выбор его узлов, вычисленный поворот звёздного рисунка, установку на коптер, переключение видимости звёзд и паузу анимации.

```sh
npm run figures
npm run audit:figures
```

В рисунке модуля 87 твёрдых деталей, в коптере с модулем — 130. Геометрический аудит проверяет реальные формы деталей, их опоры и порядок отрисовки: 11 состояний глубины и 61 промежуточное состояние разборки/отделения. Это проверка корректности иллюстрации, **не инженерная валидация устройства**.

Модель звёздного рисунка вычисляет поворот синтетической конфигурации в одной плоскости по паре направлений. Это учебный пример, не полное трёхмерное решение звёздного датчика. Иллюстрации нового модуля — условная компоновка, не финальный внешний вид изделия.

Скриншоты теста: `test-results/`. Дизайн-проверка: `.taste-skill/inspect/`. Решения и оговорки: `DESIGN.md`.
